# عُهدة (Ahdah)

منصة Mobile First عربية تربط المسافرين الذين لديهم وزن متاح بمرسلين يريدون نقل عُهدة إلى نفس مدينة الوجهة. المشروع MVP فعلي مبني بـNext.js وTypeScript وPostgreSQL وPrisma وTailwind CSS.

## ما يعمل الآن

- تسجيل حساب ودخول آمن بجلسات HttpOnly وكلمات مرور مشفرة بـ`scrypt`.
- الحساب نفسه يعمل كمرسل أو مسافر.
- إنشاء شحنة تشمل المسار والوزن والأبعاد والمحتويات والصور والقيمة والموعد والمستلم.
- إنشاء رحلة تشمل المسار والموعد وشركة الطيران والوزن المتاح.
- مطابقة فعلية حسب المدن والموعد والوزن وحالة الرحلة.
- تقديم عروض أسعار ومقارنتها وقبول عرض واحد.
- حجز مبلغ تجريبي عند قبول العرض.
- فحص العُهدة الإلزامي: قائمة تحقق، إقرار المسافر، وصور فحص جديدة.
- رقم مرجعي وQR فريد لكل عُهدة.
- سجل زمني للحالات من الطلب الجديد حتى التسليم.
- تأكيد الوصول والتسليم عبر QR ورمز OTP صالح لعشر دقائق.
- تقييم متبادل بعد التسليم.
- واجهة عربية RTL متجاوبة، حالات تحميل وخطأ وفراغ، وواجهات API أساسية.

## المتطلبات

- Node.js 22+
- PostgreSQL 16+ (أو Docker)
- npm

## التشغيل المحلي

```bash
cp .env.example .env
docker compose up -d
npm install
npx prisma migrate deploy
npm run db:seed
npm run dev
```

افتح `http://localhost:3000`.

حسابات التجربة بعد تشغيل seed:

- `sender@ahdah.sa` / `Demo1234!`
- `traveler@ahdah.sa` / `Demo1234!`

في وضع التجربة يكون OTP هو `246810` ويظهر أيضًا في صفحة التسليم. عطّل ذلك في الإنتاج عبر `ENABLE_DEMO_OTP=false`.

## أوامر الجودة

```bash
npm run lint
npm run typecheck
npm test
npm run build
```

GitHub Actions يشغّل PostgreSQL مؤقتًا ثم lint وtypecheck والاختبارات وbuild على كل Push وPull Request.

## مسار التجربة الكامل

1. ادخل بحساب المرسل وأنشئ شحنة بصور.
2. ادخل بحساب المسافر وأضف رحلة مطابقة.
3. افتح المطابقات وقدّم سعرًا.
4. عد لحساب المرسل وقارن العرض ثم اقبله.
5. بحساب المسافر افتح العُهدة، أكمل بنود الفحص وارفع صور الفحص.
6. حدّث الحالة إلى «مع المسافر» ثم «وصلت للوجهة».
7. افتح رابط QR، أرسل OTP وأدخل `246810`.
8. بعد التسليم، يقيم كل طرف الآخر من صفحة العُهدة.

## API

الجلسة نفسها المستخدمة في الويب مطلوبة للمسارات المحمية:

- `GET /api/health`
- `GET|POST /api/shipments`
- `GET|POST /api/trips`
- `GET /api/matches?tripId=...`
- `GET /api/qr/:token`

إنشاء شحنة عبر API يقبل `photoUrls` بصيغة روابط HTTPS أو Data URL. واجهة الويب ترفع الملفات مباشرة عبر Server Actions.

## بنية المشروع

```text
src/app/                 صفحات App Router وServer Actions وAPI routes
src/lib/services/        قواعد أعمال العُهدة والمطابقة والتسليم
src/lib/adapters/        بدائل التخزين والرسائل والدفع
src/components/          مكونات واجهة RTL مشتركة
prisma/                  المخطط وبيانات التجربة والترحيل
tests/                   اختبارات قواعد المجال
```

## الخدمات الخارجية المؤجلة

لا يحتاج الـMVP إلى API مدفوع. البدائل الحالية:

- التخزين: الصور تحفظ كـData URL في PostgreSQL (`MockDatabaseStorageAdapter`). للإنتاج يُستبدل بـS3/R2 دون تغيير قواعد الأعمال.
- الرسائل: OTP يطبع في سجل الخادم (`ConsoleMessagingAdapter`). للإنتاج يُستبدل بمزود SMS سعودي.
- الدفع: حجز وتحرير المبلغ محاكاة داخل قاعدة البيانات (`MockPaymentAdapter`). للإنتاج يُستبدل ببوابة دفع مرخصة.

قبل الإطلاق العام ستحتاج اختيار مزود تخزين، مزود SMS، بوابة دفع، وسياسة قانونية واضحة للمواد المسموحة والتأمين والتحقق من الهوية. هذه ليست مطلوبة لتجربة الـMVP محليًا.

## ملاحظات أمنية للانتقال إلى الإنتاج

- غيّر `SESSION_SECRET` إلى قيمة عشوائية طويلة.
- عطّل `ENABLE_DEMO_OTP`.
- أضف rate limiting لمسارات الدخول وإرسال OTP.
- انقل الصور من قاعدة البيانات إلى object storage مع فحص ملفات ومكافحة برمجيات خبيثة.
- أضف تحقق الهوية، سياسات المواد المحظورة، وآلية نزاعات قبل استقبال معاملات حقيقية.
